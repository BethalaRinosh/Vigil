How are these scores calculated?

Per-process score

0.40 × Need pressure + 0.35 × Competition + 0.25 × Sequence fragility

  • Need pressure: average of Need ÷ (Need + Available) per resource, expressed as a percentage. Zero Need contributes zero.
  • Competition: average fraction of other processes that hold or still claim each resource this process needs.
  • Sequence fragility: normalized position in the deterministic safe sequence. Later positions score higher; a blocked process scores 100.

System score

0.35 × Utilization + 0.35 × Sequence scarcity + 0.30 × Slack pressure

  • Utilization: total allocated instances ÷ (allocated + Available) × 100.
  • Sequence scarcity: 100 when no safe sequence exists; otherwise min(100, 100 ÷ √number of safe sequences).
  • Slack pressure: 100 for negative slack; otherwise 100 ÷ (1 + minimum slack).

System bands: Low 0–24, Medium 25–49, High 50–74, Critical 75–100. An unsafe state is always Critical. Distinct safe-sequence enumeration stops at 1,000; a capped count is shown as ≥1,000. This is a bounded heuristic, not machine learning, a probability, or a replacement for the formal safety check.

WORKSPACE / 06

Policy comparison

Compare conservative safety checks against a naive “grant if available” policy.

CONTROLLED EXPERIMENT

Run the same workload through both policies

SEEDED · REPRODUCIBLE

Both policies receive the exact same ordered process requests. Banker's Algorithm grants only if the tentative state remains safe. The naive policy grants whenever the request is within Need and currently Available, without checking the resulting safety state.

A fixed seed reproduces the same workload. Change the seed to test a different workload. Requests beyond a process's remaining Need are rejected by both policies; requests beyond Available must wait. This is a deterministic simulation, not a statistical proof of every possible workload.
